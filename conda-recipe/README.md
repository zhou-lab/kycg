# Conda recipe for kycg

Builds the `kycg` binary and publishes it to the **zhou-lab** channel.

## Install (end users)

```sh
conda install -c zhou-lab -c conda-forge kycg
```

This installs the `kycg` command. Knowledgebases are **not** shipped in the
package — they are fetched into the user's own store on demand:

```sh
kycg fetch          # browse the catalogue and choose
```

That split is deliberate. The compendium is hundreds of megabytes and versioned
independently of the software, so packaging it would make every data update a
software release. What the binary *does* carry is the registry: the tag and
digest of each collection it can verify, visible with `kycg --version`.

## Build & upload (maintainers)

Requires `conda-build` and `anaconda-client`:

```sh
conda install -n base conda-build anaconda-client

# Build (Linux + macOS; Windows is skipped). conda-forge supplies zlib + libcurl.
conda build -c conda-forge conda-recipe/

# Upload the built package to the zhou-lab channel
anaconda login
anaconda upload -u zhou-lab $(conda build -c conda-forge conda-recipe/ --output)
```

## Automated builds (CI)

`.github/workflows/conda-build.yml` runs `conda build` on every push/PR to
`main` across **linux-64** and **osx-arm64** (Intel `osx-64` is dropped — GitHub
is retiring its Intel macOS runners, so those jobs queue indefinitely),
uploading each package as a build artifact, and publishes to the `zhou-lab`
channel on a `vX.Y.Z` tag (guarded so the tag must match the recipe version).
Publishing needs an `ANACONDA_TOKEN` repository secret with upload rights to the
org.

A separate `selftest` job runs `make test`. The recipe's own test commands only
prove the binary runs; the statistics are what kycg is for, and a package whose
numbers had drifted would otherwise build and publish clean.

Cutting a release:

```sh
# bump `version` in conda-recipe/meta.yaml and KYCG_VERSION in src/kycg.h,
# commit, then:
git tag -a v0.4 -m "kycg 0.4" && git push origin v0.4
```

## Notes

- **In-repo build.** The recipe builds the checked-out tree (`source: path: ..`),
  including the `external/YAME/` submodule and YAME's nested `htslib`, so a
  release build is just: check out the `vX.Y.Z` tag, then `conda build`. Keep
  `version` in `meta.yaml` and `KYCG_VERSION` in `src/kycg.h` in sync with the
  tag.
- **Submodule.** `external/YAME/` must be checked out
  before building (`git submodule update --init --recursive`); `path:` copies
  whatever is on disk. htslib is vendored inside YAME rather than being a
  submodule of its own, so `--recursive` has nothing to recurse into. Its
  `config.h` is committed upstream, so no
  autoconf run is needed; `version.h` is generated by htslib's own Makefile.
- **Rebuilds the vendored static libs.** `external/YAME/libyame.a` and
  `external/YAME/htslib/libhts.a` are untracked build products that `path:`
  copies anyway. `build.sh` deletes them (and the stale `.o`) so they rebuild
  for the target arch — linking the author's arm64 objects into a linux-64
  package would fail at load time rather than at build time.
- **Flag handling.** The vendored Makefiles have rigid `CFLAGS` and ignore
  `CPPFLAGS`, so `build.sh` bakes conda's compile flags into `CC` (which every
  sub-make uses verbatim). `LDFLAGS` is expanded explicitly by the link rule —
  make imports the environment into a variable, but an explicit recipe never
  expands it on its own, and conda-forge puts `-L$PREFIX/lib` only there.
- **libcurl is optional to kycg but required here.** kycg's Makefile probes
  `curl-config` and silently builds without network support if it is missing —
  which for a *packaged* build would mean a `kycg fetch` that cannot fetch, and
  it would pass a naive smoke test. `meta.yaml`'s test greps `kycg --version`
  for `fetch available` so that failure cannot ship — asserting the working
  state positively, since the failure banner itself contains the word
  "libcurl" and a negative grep would match both.
- **Dependencies.** Only zlib and libcurl (both from conda-forge, with
  `run_exports` that pin the runtime automatically). Make sure conda-forge is on
  your channel list when building.
